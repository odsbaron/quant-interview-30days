# 量化数据工程师

## 岗位主线

量化数据工程师的职责不是“把数据搬进数据库”，而是让任何下游使用者都能回答：**这条数据从哪里来、何时可见、代表什么、经历过什么变换、现在是否可信**。

## 输入—处理—交付

| 环节 | 关键内容 | 应交付的证据 |
|---|---|---|
| 接入 | 行情协议、基本面、另类数据、跨市场源 | 原始包/文件、序列号、源时间与接收时间、许可信息 |
| 标准化 | 标的主数据、价格/数量单位、时区、交易日、公司行动 | 数据字典、映射版本、有效期与变更记录 |
| 质量控制 | 完整性、唯一性、及时性、一致性、合理性 | 规则命中、质量分、隔离区、修复/重放记录 |
| 状态重建 | Tick 排序、订单生命周期、订单簿快照与增量 | 可确定回放的事件流、缺口与恢复标记 |
| 服务 | 批处理、流处理、特征接口、查询与归档 | SLA/SLO、schema 版本、血缘、陈旧度和访问审计 |

## 核心能力

### 时间语义

要同时保留交易所事件时间、网关/网卡接收时间、处理时间与业务生效时间。研究回测使用哪个时间必须显式声明；基本面和公司行动还需要“事实有效时间 + 系统获知时间”的双时态模型。

### 数据契约

契约不只列字段类型，还要定义单位、精度、主键、排序、缺失、重复、修订、有效期、兼容策略、质量阈值和降级行为。字段新增可以向后兼容，语义变更必须升级版本。

### 质量与恢复

检测链应覆盖协议层序号、事件层状态机、统计层异常和业务层不变量。修复不能抹掉证据：保留原始值、修复值、规则版本、原因码和受影响范围；无法确定恢复时应隔离，而不是凭插值伪造成交。

### 性能与可观测性

性能指标至少区分吞吐、端到端延迟、高分位尾延迟、陈旧度、积压、丢包与恢复时间。优化前先用追踪拆分接入、解析、清洗、特征、存储各段，不用平均延迟掩盖尖峰。

## 面试题判断

- 问“如何清洗”时，先定义异常与正确语义，再谈算法。
- 问“如何设计管道”时，先给数据契约、时间模型、分区键和一致性，再谈技术栈。
- 问“如何优化”时，先给负载模型和性能预算，再说明测量、定位、改动与回归验证。
- 问“多源融合”时，先解决实体、时间、单位和版本，再讨论模型。

## 与其他岗位的接口

- 向研究员提供 point-in-time 数据与质量权重，不能只交一张“最终正确”的历史表。
- 向回测架构师提供可重放事件流、交易日历和公司行动版本。
- 与开发工程师共同定义协议适配、缓存/存储、监控、恢复和发布兼容性。
- 向治理方提供数据血缘、权限、脱敏、保留与删除证据。
