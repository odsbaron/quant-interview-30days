## 本章定位

本章从订单簿状态语义出发，贯通重建、存储、实时计算、微观结构特征、低延迟和 AI，是行情工程与策略研究的接口层。

回答本章问题时，不应停留在工具名罗列；需要把数据语义、处理步骤、系统状态、验证指标和失败边界连成闭环。

## 知识框架

### 2.1 订单簿基础

- **核心概念：**订单簿由买卖方向、价格档位、挂单量、订单/事件序号与时间组成；价差、深度和中间价刻画交易成本与流动性。
- **方法 / 系统组件：**用价格有序结构加订单 ID 索引维护增量事件，以快照初始化并顺序应用新增、撤单和成交；从最佳档与多档累计量计算价差和深度。
- **指标 / 约束：**更新必须保持价格优先/时间优先和序列连续；极端行情下先确认是真实流动性变化还是快照冻结/增量丢失。

### 2.2 数据清洗与预处理

- **核心概念：**快照与逐笔数据的语义、粒度和恢复方式不同：快照给状态，逐笔给状态转移。
- **方法 / 系统组件：**完成协议解析、字段标准化、序列校验、去重、乱序缓冲、异常标记与盘口重建；断线重连时以新快照重置基线并补放可验证增量。
- **指标 / 约束：**不可把逐笔成交当委托更新，也不可在未知基线继续累计；质量控制需平衡重排窗口、延迟和准确性。

### 2.3 数据存储与查询优化

- **核心概念：**订单簿存储既要支持时间范围扫描，又要支持按标的回溯版本与快速恢复最新状态。
- **方法 / 系统组件：**热层用内存/时序库，分析层用 ClickHouse/Doris，冷层用 Parquet；按交易日和标的分区/分桶，排序键含标的与时间，Delta/Iceberg 保存增量版本。
- **指标 / 约束：**分区不能过细，索引要匹配查询谓词；压缩需保持价格精度、档位结构与随机解码能力。

### 2.4 实时数据处理

- **核心概念：**实时处理是从接入、清洗、状态盘口、指标计算到下游发布的有状态流。
- **方法 / 系统组件：**Kafka 承载可回放日志，Flink/Kafka Streams 按标的分区维护盘口和窗口指标，Checkpoint 与幂等输出保障一致性，并以跨源/快照校验纠偏。
- **指标 / 约束：**关注输入到事件时间的延迟、积压、状态大小、恢复时间和输出一致性；不能只监测消费者处理时间。

### 2.5 高级分析与建模

- **核心概念：**高级分析从价差、深度、订单流不平衡、撤单率和流动性弹性中提取短期价格与风险信号。
- **方法 / 系统组件：**先定义可复现的盘口特征，再做市场状态分层、实时异常检测或监督模型；Level 2/3 的选择取决于信息增益、成本与处理能力。
- **指标 / 约束：**标签必须延后生成并计入交易成本；闪崩/流动性枯竭属于分布外状态，需单独验证，防止噪声和前瞻偏差。

### 2.6 低延迟优化

- **核心概念：**低延迟优化覆盖数据结构、内存布局、语言运行时、网络与 FPGA/GPU，不同延迟来源需要不同手段。
- **方法 / 系统组件：**以性能剖析定位解析、锁竞争、缓存未命中、GC、网络和持久化瓶颈；再采用数组/跳表、对象池、绑核、零拷贝、批量或硬件流水线。
- **指标 / 约束：**报告中应给出延迟分解和前后对照，兼顾吞吐、正确性、可维护性与故障切换，而非只报平均延迟。

### 2.7 机器学习与AI应用

- **核心概念：**机器学习任务包括方向/波动预测、状态识别、异常检测、做市决策和数据补全，输入核心仍是盘口时序与微观结构。
- **方法 / 系统组件：**构造价差、深度、订单流不平衡、撤单率和多尺度窗口特征；按任务选 LSTM/Transformer、无监督+监督检测或强化学习，并用联邦学习处理跨所协作。
- **指标 / 约束：**处理非平稳、高频噪声、类别不平衡和推理时延；评估同时覆盖预测、策略收益、成本、漂移和隐私通信开销。

## 高频易错点

- 混淆成交、委托与盘口快照。
- 无基线继续应用增量。
- 把价差扩大一律判异常。
- 只谈模型不谈可成交和成本。
- 优化数据结构却忽略单标的顺序。

## 复习顺序

1. **核心必会：**先掌握 2.1—2.2 的盘口结构、快照/增量与恢复，再能手算价差、深度和基本不平衡。
2. **进阶：**进阶到 2.3—2.7，重点打通版本存储、流状态、异常检测、性能剖析与模型特征。
3. **查漏：**回查 Level 2/3、闪崩、断线重连、压缩局部解码和标签时点等边界。
