## 本章定位

本章建立量化数据工程师处理逐笔行情的第一性流程：先理解事件语义，再完成质量、清洗、标准化，最后把结果放入低延迟分布式管道。

回答本章问题时，不应停留在工具名罗列；需要把数据语义、处理步骤、系统状态、验证指标和失败边界连成闭环。

## 知识框架

### 1.1 Tick数据基础

- **核心概念：**Tick 是逐笔成交/报价的非均匀高频时序，需区分 Level 1 顶层行情与 Level 2 深度/逐笔信息，并明确交易日与自然日的差别。
- **方法 / 系统组件：**以交易所序列号、事件时间、接收时间和交易日历为主线完成去重、有限乱序重排、缺口标记/重传及订单簿重建；夜盘与日盘须统一交易日映射。
- **指标 / 约束：**关注完整率、重复率、乱序深度、时钟偏差和处理延迟；不能把同一时间戳的合法多笔成交误删，也不能用插值伪造原始成交。

### 1.2 数据质量检查

- **核心概念：**质量检查覆盖完整性、准确性、一致性、及时性与唯一性，多源报价偏差既可能是数据故障，也可能是真实市场差异。
- **方法 / 系统组件：**建立接入校验、动态基线/滑窗检测、跨源对账、根因定位、分级告警和回放修复闭环；时间延迟需沿交易所、网络、解析与计算链逐层定位。
- **指标 / 约束：**阈值应随波动状态调整；告警同时记录源、标的、序列号和延迟分位数，并保留原始数据及修复血缘。

### 1.3 数据清洗技术

- **核心概念：**清洗对象包括价格突刺、零/负值、静态冻结、重复、缺失、乱序和时间跳变，处理前必须区分真实极端行情与技术噪声。
- **方法 / 系统组件：**实时层用滑窗、MAD/Z-score、业务边界和跨源校验快速标记，离线层再回溯；历史大批量数据按标的/交易日分区并行，修复结果与原值并存。
- **指标 / 约束：**清洗规则必须可解释、可回放、可版本化；准确性增益需与延迟、吞吐和误杀率一起评估。

### 1.4 数据标准化

- **核心概念：**标准化统一时间、时区、交易日、价格/数量单位、币种、字段命名、精度和品种代码，使跨交易所数据可比。
- **方法 / 系统组件：**通过规范化 schema、参考数据/汇率表、事件时间水位线、版本化解析器和兼容层应对格式变化；TB 级处理采用分区、列式批量与增量流水线。
- **指标 / 约束：**避免浮点精度损失、汇率时点错配和夏令时/节假日映射错误；schema 演进须向后兼容并有契约测试。

### 1.5 低延迟数据处理

- **核心概念：**低延迟不是单点提速，而是采集、序列化、网络、队列、计算、状态与存储的端到端预算管理。
- **方法 / 系统组件：**使用紧凑二进制协议、零拷贝/内存池、无锁结构、异步 I/O、批量与向量化；按规则计算、GPU 并行或 FPGA 固定流水线的负载特征选择加速方式。
- **指标 / 约束：**同时看端到端及各阶段延迟分位数、吞吐、积压、丢包和错误率；不能用跳过校验换取表面低延迟。

### 1.6 分布式数据处理

- **核心概念：**分布式 Tick 处理的核心是正确分区、事件时间语义、有状态计算、容错与弹性，而非简单增加节点。
- **方法 / 系统组件：**按标的/交易所并兼顾热点分区，使用 Flink 原生流或 Spark 微批；用水位线、Checkpoint/状态后端、幂等 sink 或事务保证 Exactly-Once，并以 Kubernetes 扩缩容应对开盘洪峰。
- **指标 / 约束：**防止数据倾斜、跨节点时钟漂移和检查点阻塞；扩容后仍要保持同一标的顺序与状态归属。

### 1.7 前沿技术与趋势

- **核心概念：**前沿主题围绕 FPGA 解析、PySpark/Dask、WebSocket/FIX、机器学习异常检测及夜盘零丢失架构，评价标准仍是可落地性。
- **方法 / 系统组件：**先按负载拆分可硬件化路径与灵活软件路径，再结合协议延迟、分布式执行、模型误报和状态恢复设计混合架构。
- **指标 / 约束：**不要把新技术等同于必然更快；需说明开发周期、数据搬运、可观测性、合规和故障降级成本。

## 题型与答题框架

- **概念 / 说明题（6 题）：**先给出对象的精确定义与数据边界，再说明字段或组成、工作机制、量化岗位用途，最后补充不适用条件和常见混淆。
- **方案设计 / 故障处理题（25 题）：**按“输入与语义 → 清洗/计算 → 状态与存储 → 输出 → 监控与恢复”展开；排障题先建立基线并分层定位，再给验证实验、修复和回归。
- **比较 / 选型题（6 题）：**先固定负载和 SLO，再从延迟、吞吐、一致性、状态/查询模式、容错、成本、运维与合规逐维比较，给出条件化结论而非绝对优劣。
- **案例 / 复盘题（3 题）：**交代业务规模与约束，给出原始指标和证据，说明定位过程、关键改动、验证口径、剩余风险；没有亲历数据时使用明确的假设案例。

本章的答案最终要落到可验证约束，例如：关注完整率、重复率、乱序深度、时钟偏差和处理延迟；阈值应随波动状态调整；清洗规则必须可解释、可回放、可版本化；避免浮点精度损失、汇率时点错配和夏令时/节假日映射错误；同时看端到端及各阶段延迟分位数、吞吐、积压、丢包和错误率；防止数据倾斜、跨节点时钟漂移和检查点阻塞；不要把新技术等同于必然更快。

## 高频易错点

- 把时间戳相同等同于重复。
- 对真实价格跳跃直接插值。
- 只报告平均延迟不看尾部。
- 混淆事件时间、接收时间和处理时间。
- 宣称 Exactly-Once 却未说明 source 与 sink。

## 复习顺序

1. **核心必会：**先掌握 1.1—1.4 的 Tick 语义、质量、清洗和标准化，并能独立解释一条数据从交易所到标准层的变化。
2. **进阶：**再学习 1.5—1.7 的延迟分解、Flink 状态/一致性、硬件与机器学习，形成端到端方案。
3. **查漏：**最后按夜盘交易日、schema 变化、乱序/断点和框架选型四类边界逐题回查。
