# 16 文档、测试与持续交付

> 来源：量化开发工程师.pdf（原本地参考：`../../量化开发工程师.pdf`）；物理页码：PDF 第 726-763 页；二级主题数：4；题数：14。

## 本章定位

本章将质量保障延伸到性能、故障、发布和知识传承：微基准证明局部优化，确定性仿真证明业务正确，混沌和时间旅行复现系统故障，兼容发布与文档自动化则让变更可验证、可回滚、可交接。

## 知识框架

### 16.1 单元与微基准测试

- 核心概念：微基准需防死码消除、固定频率与输入；确定性撮合仿真用全局序列而非墙上时钟；覆盖率只是测试充分性的代理。
- 工程组件：Google Benchmark、DoNotOptimize/ClobberMemory、CPU 隔离、单线程 Event Bus、golden replay、分支/MC-DC 与缺陷统计。
- 性能与约束：报告分布和环境元数据；覆盖目标优先覆盖状态迁移、边界与故障路径，不能用无断言测试堆高行覆盖。

### 16.2 混沌工程与故障注入

- 核心概念：混沌实验验证不变量而非制造故障；UDP 丢包检验订单簿恢复，机房分区检验多活一致性，时间旅行平台用快照+不可变事件复现。
- 工程组件：Chaos Mesh/netem、影子订单流、Raft/多活探针、PTP 事件采集、确定性回放与快照索引。
- 性能与约束：只在隔离/影子环境或获批窗口注入，定义停止条件；验证零重复订单、状态收敛、RPO/RTO 和证据完整。

### 16.3 回滚与蓝绿发布

- 核心概念：数据库演进采用 expand/contract 保持旧版本读新 Schema；灰度按指标渐进放量，Binlog 时间切片负责数据恢复，回滚窗口决定业务损失。
- 工程组件：可空新增列/兼容视图、Flagger、Prometheus 门禁、ROW Binlog/GTID、影子库和损失上界模型。
- 性能与约束：应用回滚与数据回滚分开设计；不可逆变更延后清理，Binlog 逆操作先在副本验证，并量化中断期间错失、库存和重连损失。

### 16.4 文档自动化与知识管理

- 核心概念：文档应由代码与图的文本源自动生成；语义搜索用于召回模块知识，但必须经过权限过滤和来源引用。
- 工程组件：Doxygen XML、Sphinx/Breathe、PlantUML/Graphviz、CI 产物、Confluence API、双塔向量检索与审计。
- 性能与约束：文档构建失败阻断发布或显式告警；中文字体与渲染版本固定，问答只返回用户有权访问的仓库片段。

## 题型与答题框架

- 测试题先定义不变量和噪声源，再给数据、环境、断言、统计与门禁。
- 混沌题按假设、注入范围、观测、停止条件、恢复和复盘回答。
- 发布题分别描述代码、配置、Schema 和数据状态的前向兼容/回滚。
- 文档题给单一源、自动构建、发布目标、链接校验和权限策略。

## 高频易错点

- 微基准被编译器删掉，或频率/调度不固定却比较纳秒差异。
- 确定性测试仍读取系统时间、随机源或非稳定线程顺序。
- 用 95% 行覆盖证明无缺陷，忽略分支和业务断言。
- 混沌实验没有停止条件，污染生产或真实订单。
- 应用回滚时强行逆向 Schema，扩大停机和数据风险。
- 知识机器人绕过文档权限，泄露源码与策略细节。

## 复习顺序（核心必会/进阶/查漏）

- 核心必会：可信微基准、确定性仿真、混沌不变量、expand/contract。
- 进阶：时间旅行回放、Flagger 指标门禁、Binlog 时间切片。
- 查漏：覆盖率边际、回滚损失上界、文档同步与语义检索权限。
