## 本章定位

本章以架构视角汇总清洗、存储、管道、消息、低延迟、容错与新硬件，强调边界和故障域。

回答本章问题时，不应停留在工具名罗列；需要把数据语义、处理步骤、系统状态、验证指标和失败边界连成闭环。

## 知识框架

### 21.1 数据清洗与预处理

- **核心概念：**架构层预处理把 Tick/盘口、公司行动和另类数据转成可信标准层。
- **方法 / 系统组件：**流式清洗乱序/异常，股票拆分分红用生效时间和复权因子维护原始/复权双视图，另类数据质量从覆盖、清晰、时效、偏差和下游效用验证。
- **指标 / 约束：**准确性与性能通过分层校验权衡；所有修复可追溯，复权和因子不得泄漏未来公告。

### 21.2 数据存储与管理

- **核心概念：**系统需为 PB 另类数据、TB 盘口和跨境多中心提供分层、加密、可查询存储。
- **方法 / 系统组件：**内存/Flink 状态承接热计算，时序/列式库承接近线，对象存储承接冷数据；按市场/标的/时间分片，缓存与预聚合加速，跨境复制加密并遵守驻留。
- **指标 / 约束：**评估成本、延迟、吞吐、恢复、生命周期和合规；Tick 事件与盘口状态采用不同表模型。

### 21.3 数据管道设计

- **核心概念：**数据管道连接采集、规范化、计算、质量、存储与消费，是量化系统的数据契约。
- **方法 / 系统组件：**用消息日志、二进制序列化、按键分区与 Flink 状态；乱序靠序列/水位线，FPGA/GPU 只加速解析或批量热点，观测贯穿各阶段。
- **指标 / 约束：**设计需给出 schema、顺序、一致性、延迟预算、过载和恢复；案例复盘用基线—定位—变更—验证。

### 21.4 系统架构设计

- **核心概念：**系统架构由接入、消息、处理、状态/存储、服务、监控和安全组成。
- **方法 / 系统组件：**Kafka/Pulsar 按持久、分层存储、租户和运维选型，订单簿按标的分片并保持单键顺序，弹性扩展与快照/日志容错，质量模块隔离坏数据。
- **指标 / 约束：**组件堆叠不等于架构；明确数据所有权、接口、故障域、容量和一致性边界。

### 21.5 低延迟优化

- **核心概念：**低延迟优化横跨部署拓扑、网络、序列化、内存、CPU/GPU/FPGA 和数据结构。
- **方法 / 系统组件：**先分解延迟，再用共址/RDMA/内核旁路、零拷贝、环形缓冲、紧凑结构、批量或硬件流水线；Kafka 与 ZeroMQ 按可靠日志/轻量传输取舍。
- **指标 / 约束：**看 p99/p999、抖动、吞吐、丢失和正确性；内存结构要考虑容量、回收与快照恢复。

### 21.6 分布式系统与容错

- **核心概念：**分布式容错通过分片扩吞吐、副本保可用、日志/检查点恢复、共识维护关键元数据。
- **方法 / 系统组件：**行情按标的分片，Kafka/Pulsar 用 key/offset/幂等去重和顺序，跨中心关键控制面用 Raft 类共识，节点/倾斜由监控触发重调度与重放。
- **指标 / 约束：**CAP 按链路回答；共识、同步副本和强一致不可无差别放入热路径，容灾体系需演练 RPO/RTO。

### 21.7 新技术与趋势

- **核心概念：**趋势包括在线异常推理、亚微秒时间、RDMA、知识图谱、FPGA 与计算贴近性。
- **方法 / 系统组件：**接入层硬件时间戳/校时，RDMA 降低拷贝与内核开销，FPGA 处理稳定盘口算子，知识图谱统一多源实体关系，模型服务量化/批流协同。
- **指标 / 约束：**评估网卡/交换机/机房距离、开发难度、可观测和降级；物理距离与时钟误差是硬约束。

## 题型与答题框架

- **概念 / 说明题（6 题）：**先给出对象的精确定义与数据边界，再说明字段或组成、工作机制、量化岗位用途，最后补充不适用条件和常见混淆。
- **方案设计 / 故障处理题（26 题）：**按“输入与语义 → 清洗/计算 → 状态与存储 → 输出 → 监控与恢复”展开；排障题先建立基线并分层定位，再给验证实验、修复和回归。
- **比较 / 选型题（7 题）：**先固定负载和 SLO，再从延迟、吞吐、一致性、状态/查询模式、容错、成本、运维与合规逐维比较，给出条件化结论而非绝对优劣。
- **案例 / 复盘题（4 题）：**交代业务规模与约束，给出原始指标和证据，说明定位过程、关键改动、验证口径、剩余风险；没有亲历数据时使用明确的假设案例。

本章的答案最终要落到可验证约束，例如：准确性与性能通过分层校验权衡；评估成本、延迟、吞吐、恢复、生命周期和合规；设计需给出 schema、顺序、一致性、延迟预算、过载和恢复；组件堆叠不等于架构；看 p99/p999、抖动、吞吐、丢失和正确性；CAP 按链路回答；评估网卡/交换机/机房距离、开发难度、可观测和降级。

## 高频易错点

- 组件越多越“完整”。
- 未定义单键顺序与状态所有权。
- 强一致覆盖所有链路。
- 只压测正常流量不演练故障。
- 新硬件无回退软件路径。

## 复习顺序

1. **核心必会：**先掌握 21.1—21.4，能画数据生命周期、组件职责和数据契约。
2. **进阶：**再攻克 21.5—21.7 的尾延迟、容错、RDMA/FPGA 与计算贴近性。
3. **查漏：**用容量、SLO、RPO/RTO、时钟、跨境和降级场景检验架构。
